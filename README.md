# Klipmo Wallpaper

A wallpaper site with separate phone and laptop downloads, live (video) wallpaper
support, and a full admin panel — no server, no database, hosted free on Netlify.

Everything in this repo is a starting point with sample content. The 10 static
wallpapers and 1 live wallpaper are original, procedurally-generated placeholder
art (not real photos or real "premium" wallpapers) — replace them with your own
through the admin panel before you launch.

---

## 1. How this is built (read this once)

- **The site itself is static HTML/CSS/JS**, generated by a tool called Eleventy
  (11ty). There is no server and no database. This matters for your security
  concern: most hacking targets a server or a database — this site doesn't have
  either, so that entire category of attack doesn't apply.
- **The admin panel** (`/admin`) is [Decap CMS](https://decapcms.org/), a free,
  open-source editor that runs entirely in your browser. When you save a change,
  it commits a file directly to your GitHub repository. Netlify then rebuilds
  the site automatically.
- **Login for the admin panel** is handled by Netlify Identity — Netlify's own
  authentication system. You control exactly who can log in (just you, unless
  you invite someone else).

This is the standard, well-established way to run a free, low-maintenance,
hard-to-hack content site. It's the same pattern used by thousands of small
publications and portfolio sites.

## 2. One-time setup

You'll need two free accounts: **GitHub** and **Netlify**.

### Step 1 — Put the code on GitHub
1. Create a free account at [github.com](https://github.com) if you don't have one.
2. Create a new **empty** repository (no README, no .gitignore) named `klipmo-wallpaper`.
3. On your own computer, unzip this project, then run inside the folder:
   ```
   git init
   git add .
   git commit -m "Initial site"
   git branch -M main
   git remote add origin https://github.com/YOUR-USERNAME/klipmo-wallpaper.git
   git push -u origin main
   ```

### Step 2 — Deploy on Netlify
1. Create a free account at [netlify.com](https://netlify.com) (you can sign up with your GitHub account).
2. Click **Add new site → Import an existing project → GitHub**, and pick your `klipmo-wallpaper` repo.
3. Netlify will detect `netlify.toml` automatically. Build command: `npm run build`. Publish directory: `_site`. Click **Deploy**.
4. After the first deploy finishes, you'll get a free URL like `https://klipmo-wallpaper-xyz.netlify.app`. You can rename this in **Site configuration → Change site name**, or add a custom domain later (custom domains cost money for the domain name itself; the Netlify hosting stays free).

### Step 3 — Turn on the admin panel (Netlify Identity + Git Gateway)
1. In your Netlify site dashboard: **Site configuration → Identity → Enable Identity**.
2. Under **Registration preferences**, set it to **Invite only** (important — this stops strangers from signing themselves up as admins).
3. Scroll to **Services → Git Gateway → Enable Git Gateway**. This is what lets the admin panel save changes to GitHub on your behalf, without you ever handling a GitHub token.
4. Go to the **Identity** tab and click **Invite users**. Invite your own email address.
5. Check your email, click the invite link — it will take you to your site and prompt you to set a password.
6. You're now an admin. Visit `https://your-site.netlify.app/admin/` any time to log in and edit the site.

### Step 4 — Update your site URL in settings
Once you know your real Netlify URL (or custom domain), open `/admin/` → **Site settings → General site settings**, and update the **Site URL** field to match exactly. This is used for the sitemap and social sharing previews.

That's the whole setup. From here on, you never need to touch code again — everything below can be done from `/admin/`.

## 3. Using the admin panel

Go to `yoursite.com/admin/` and log in.

- **Wallpapers** — add, edit, or delete wallpapers. Choose **Static image** or **Live (video loop)** as the type, then fill in only the fields relevant to that type (the form shows fields for both, but a static wallpaper only needs the image fields, and a live wallpaper only needs the video + poster fields). You can fill in just a phone version or just a laptop version if that's all you have — the site adapts automatically (no broken buttons, no toggle shown if there's only one).
- **Categories** (under Site settings) — add, rename, reorder, or remove categories freely. The category name a wallpaper shows under is whatever you type into that wallpaper's **Category** field, matched against the category **slug** here.
- **General site settings** — site title, tagline, your AdSense IDs, and an **Ads enabled** on/off switch that hides every ad slot instantly if you flip it off.
- **Pages** — edit the About, Privacy, and Terms page text directly.

Every change creates a small commit behind the scenes and triggers a new deploy — usually live within a minute.

### What visitors see on a wallpaper page
- A **Phone / Laptop toggle** above the preview if both versions exist, so people can check the crop before downloading.
- Live wallpapers preview as an actual looping video, both on the detail page and (on hover) right in the browsing grid.
- Everything fades and scroll-reveals in gently — this is purely visual and degrades gracefully: if a visitor has JavaScript disabled, all content shows immediately and normally instead of staying hidden.

### Adding a new wallpaper
1. Static: fill in Title, Category, upload a thumbnail (grid preview), a phone image, and a laptop image.
2. Live: fill in Title, Category, set Type to "Live", upload a poster image (shown before the video plays) and the phone/laptop MP4 video files.
3. Publish. It appears on the homepage, its category page, and the browse-all page immediately.

Keep phone images near **1080×1920** and laptop images near **1920×1080** for a consistent look — the download buttons show whatever resolution label you type in, so keep that text accurate.

## 4. Turning on ads (Google AdSense)

1. Apply for AdSense at [adsense.google.com](https://adsense.google.com) using your live Netlify URL. Approval typically requires some real content and a bit of traffic history — this is Google's process, not something this site controls.
2. Once approved, AdSense gives you a **publisher ID** (looks like `ca-pub-1234567890123456`) and **ad slot IDs**.
3. In `/admin/ → Site settings → General site settings`, paste your publisher ID into **AdSense publisher ID**, and your slot IDs into the two slot fields.
4. Update `ads.txt` — open `/admin/`, and since `ads.txt` isn't in the CMS by default, edit it directly in GitHub (`src/ads.txt`) replacing the placeholder line with the exact line AdSense shows you under **Sites → ads.txt**. This file is required by AdSense or ads won't fully serve.
5. Ad slots are placed after the hero, and once per listing page/wallpaper page — never stacked, never full-screen, never interstitial. That was a deliberate choice so ads don't make the site annoying to use.

If you ever want ads off entirely (e.g. while waiting for approval), flip **Ads enabled** to off — every slot reverts to invisible until turned back on.

## 5. Live wallpapers — what they are and their limits

A "live wallpaper" here is a short looping video. Important honesty check: **no
website can set your phone or computer background directly** — that's a
browser security restriction on every platform, not something specific to this
site. After downloading, the visitor needs one extra step:

- **Android**: many phones support video wallpapers natively (Settings →
  Wallpaper → Live/Video wallpaper). Otherwise, a free app like *Video Live
  Wallpaper* does it.
- **iPhone**: only supports "Live Photos" (image + video pairs) as animated
  wallpapers, and only on the lock screen. A conversion app is needed.
- **Windows**: a free app called **Lively Wallpaper** (or the paid **Wallpaper
  Engine** on Steam) plays the video as the desktop background.
- **Mac**: no native support; a small free app like **Plash** does it.

All of this is written out for visitors on the **Live wallpapers** guide page
(`/guide/live-wallpapers/`), linked from every live wallpaper's download page.
Keep video files short (2–6 second loops) and under ~15–20MB so they're quick
to download.

## 6. Security — what's already handled, and what's on you

**Already handled by this setup:**
- No server code and no database means no SQL injection, no server exploits, and no exposed admin API for an attacker to hit.
- HTTPS is automatic and free on every Netlify domain.
- The admin panel requires a Netlify Identity login — set to invite-only, so nobody can self-register.
- `netlify.toml` sets security headers (Content-Security-Policy, clickjacking protection, MIME-sniffing protection) on every page.
- Visitors can only ever download files — there is no public upload form anywhere on the site, so there's no way for a stranger to push content onto your site.

**Still on you, and worth doing:**
- Use a strong, unique password for your Netlify and GitHub accounts, and turn on **two-factor authentication** on both (Netlify: Account settings → Security; GitHub: Settings → Password and authentication). This is the single biggest real-world protection available to you.
- Keep the Identity registration setting on **Invite only**, and only invite people you trust with edit access.
- **Only upload wallpapers you made yourself or have the rights to distribute.** This is the actual biggest risk for a wallpaper site — copyright, not hacking. Using someone else's photography, art, or a movie/game/franchise's official art without a license is a real legal exposure for you as the site operator, regardless of how secure the hosting is. The `/contact/` page includes a basic DMCA/takedown request form for exactly this situation.
- Review the placeholder Privacy Policy and Terms pages before turning on real ads — they're a starting template, not legal advice, and ad networks like AdSense require an accurate privacy policy to stay approved.
- Occasionally run `npm audit` in the project folder and update dependencies; this project intentionally uses very few (just Eleventy itself) to keep that surface small.

## 7. Local development (optional)

If you want to preview changes on your own computer before pushing:
```
npm install
npm run dev
```
This opens a local preview at `http://localhost:8080`. `npm run build` produces the final `_site` folder that Netlify also builds automatically on every push — you don't need to run this yourself for deployment.

## 8. Project structure

```
src/
  wallpapers/        one file per wallpaper (edited via admin, or by hand)
  _data/
    site.json            site-wide settings (editable via admin)
    categoriesData.json  category list (editable via admin)
  _includes/
    layouts/         page templates (base, wallpaper, generic page)
    partials/        header, footer, reusable macros (card, ad slot)
  css/style.css      all styling
  js/main.js         browse-page filtering
  images/uploads/    all wallpaper images & videos live here
admin/
  config.yml         defines every field the admin panel shows
  index.html         loads the admin panel
netlify.toml         build settings + security headers
```
